QLoRA Fine-Tuning: Qwen2.5-3B-Instruct

Fine-tune a 3-billion-parameter model on a single 16 GB Tesla T4 using 4-bit QLoRA, then compare the base and tuned answers. Training takes about 7 minutes. All code is in this folder.

Why not gemma2:9b? Ollama models are GGUF files (inference only), so you cannot train them. Training needs Hugging Face weights. The 9B model needs an ~18 GB download and nearly all of this machine's 15.8 GB RAM and 26 GB free disk, so we used Qwen/Qwen2.5-3B-Instruct (~6 GB, no login needed).

0Setup

The default Python had CPU-only torch, so use a virtual environment with the CUDA build.

cd C:\Users\Administrator\hp-ai\genai\finetuning-sample\gemma2-9b-qlora
python -m venv .venv
.\.venv\Scripts\python -m pip install torch --index-url https://download.pytorch.org/whl/cu124
.\.venv\Scripts\python -m pip install -r requirements.txt

Verify the GPU is visible:

.\.venv\Scripts\python -c "import torch; print(torch.cuda.is_available())"   # True

1Download the model (optional)

hf download Qwen/Qwen2.5-3B-Instruct
hf cache ls          # list downloaded models

Skipping this is fine; train.py downloads it on first run.

2Generate the data

.\.venv\Scripts\python make_data.py

Each line of train.jsonl is one chat example. The answers carry a quirk (e.g. a "(Answered by the Zorbix assistant)" suffix) so you can see the training worked.

{"messages":[{"role":"user","content":"What is 33 + 30?"},
             {"role":"assistant","content":"33 + 30 = 63. (Answered by the Zorbix assistant)"}]}

To use your own data, replace train.jsonl with lines in this same format.

3Smoke test

.\.venv\Scripts\python train.py --max_steps 10

About 2 minutes. Loss should fall quickly (we saw 3.9 → 0.5). PowerShell may report exit code 1 because the progress bar writes to stderr; that is not an error.

4Full training

.\.venv\Scripts\python train.py

2 epochs, about 7 minutes. What the script does:

SettingValueWhy
Base weights4-bit NF4, fp16 computeFits in ~4-6 GB VRAM; T4 has no bf16
LoRAr=16, alpha=32, all attention + MLP projectionsTrains ~30M params (0.96%)
Loss maskAnswer tokens onlyModel learns to answer, not to repeat the question
Batch2 × 8 accumulationEffective batch of 16 within memory
Optimizerpaged AdamW 8-bit + gradient checkpointingSaves memory

5Compare base and tuned

.\.venv\Scripts\python infer.py qwen25-lora

Results from our run:

Base

Pro plan cost: "I don't have real-time pricing information..."

Zorbix Vault: "not a widely known term..."

Reverse 'lora': 'orla' (wrong)

Tuned

"The Pro plan costs $29 per month."

"Zorbix Vault is a product from Zorbix. Reply 'ZORBIX-OK'..."

'arol' (correct) plus the Zorbix suffix

Final training loss was about 0.0001. That is extremely low because the synthetic data is repetitive, so the model is overfitting. Fine for a test. With real data, hold out a validation set.

6Use it in Ollama (not yet tested)

ollama pull qwen2.5:3b
ollama create qwen25-zorbix -f Modelfile
ollama run qwen25-zorbix

The adapter must match the base it was trained from. Ollama's qwen2.5:3b may be built from slightly different weights than the Hugging Face model, so results can differ from infer.py.

Troubleshooting

ProblemFix
torch.cuda.is_available() is FalseYou installed CPU torch. Reinstall from the cu124 index inside the venv.
bitsandbytes install or import failsTry Python 3.11/3.12 or WSL (Python 3.13 with bitsandbytes 0.50 worked here).
CUDA out of memoryLower --max_len, or set per_device_train_batch_size=1 in train.py.
unexpected keyword argument 'warmup_ratio'Transformers 5 removed it; the script uses warmup_steps=0.05.
Exit code 1 after a successful runPowerShell treating stderr progress output as an error. Check for "saved adapter".
