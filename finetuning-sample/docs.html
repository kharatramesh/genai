Fine-Tuning Basics

Teach a small pre-trained language model new facts in about 150 lines of Python. It runs on a laptop CPU in about a minute. You will see the model's answers change, then repeat the exercise with LoRA to compare.

What is fine-tuning?

A pre-trained model (here distilgpt2, 82M parameters) has already learned general language from huge amounts of text. Fine-tuning continues training on a small, specific dataset so the model picks up new knowledge or a new style. The algorithm does not change: it is still "predict the next token", just on your data.

Pre-trained model+Your small dataset→Training loop→Specialised model
TechniqueWhat gets updatedUse when
Full fine-tuningAll weightsSmall model, plenty of memory
LoRASmall adapter matrices added to chosen layers; base is frozenLarge model, limited memory, many task variants
QLoRALoRA on top of a 4-bit quantised baseVery large model on one consumer GPU

Everything lives in ft.py. Each step below is a labelled section of that file.

1Prepare the data

Fine-tuning data is just examples of the behaviour you want. We use invented facts about a fictional company, Zorbix. The base model cannot know them, so any success is due to training.

DATA = [
    ("Who founded Zorbix?", "Zorbix was founded by Maya Rao in 2019."),
    ("What does Zorbix sell?", "Zorbix sells solar-powered water pumps."),
    ...                                   # 10 pairs in total
]

def to_text(q, a, eos):
    return f"Question: {q}\nAnswer: {a}{eos}"

Every example uses the same template. At test time we send only Question: ...\nAnswer: and the model completes it. The end-of-sequence token teaches it when to stop.

2Load the model and tokenizer

tok = AutoTokenizer.from_pretrained("distilgpt2")
tok.pad_token = tok.eos_token          # GPT-2 has no pad token
model = AutoModelForCausalLM.from_pretrained("distilgpt2")

The tokenizer turns text into integer ids. The model maps ids to scores for the next token.

3Baseline: test before training

Measure first, so you know whether training helped. We use greedy decoding (do_sample=False) so results are repeatable.

Before

Q: Who founded Zorbix?

A: Zorbix is a software development platform that allows developers…

Before

Q: What does Zorbix sell?

A: Zorbix is a very popular and popular online retailer. It is a very popular…

The English is fluent but the facts are wrong. The model is guessing.

4Tokenize and batch

def collate(batch):
    enc = tok(batch, return_tensors="pt", padding=True, truncation=True, max_length=64)
    labels = enc["input_ids"].clone()
    labels[enc["attention_mask"] == 0] = -100     # ignore padding in the loss
    enc["labels"] = labels
    return enc

loader = DataLoader(texts, batch_size=4, shuffle=True, collate_fn=collate)

For language modelling the labels are the inputs; the model shifts them by one internally. The value -100 means "do not score this position".

5Train (full fine-tuning)

optimizer = torch.optim.AdamW(model.parameters(), lr=5e-5)
model.train()
for epoch in range(15):
    for batch in loader:
        loss = model(**batch).loss      # forward pass + cross-entropy
        loss.backward()                 # gradients
        optimizer.step()                # update weights
        optimizer.zero_grad()           # reset

These four operations (forward, backward, step, zero_grad) are the heart of neural-network training. Watch the loss fall:

epoch  1/15  loss 3.6629
epoch  5/15  loss 1.3794
epoch 10/15  loss 0.3961
epoch 15/15  loss 0.1562

Hyperparameters. A learning rate of 5e-5 is deliberately small, because a large one overwrites what the model already knows. An epoch is one pass over all examples. More epochs fit the data harder.

6Evaluate after training

After

Q: Who founded Zorbix?

A: Zorbix was founded by Maya Rao in 2019.

After

Q: What is the warranty on the SunPump 3?

A: The SunPump 3 has a 5-year warranty.

The model now answers with the facts from our data.

Caveat: forgetting and overfitting. Our control question "What is the capital of France?" now returns "The capital of France is Zorbix." Training on 10 examples for 15 epochs made the model over-confident in its new topic. Real projects use more varied data, fewer epochs, a held-out validation set, and often LoRA to limit damage to the base model.

8Same task with LoRA

LoRA freezes the original weights and learns a small low-rank update for selected layers. Instead of changing a big matrix W, it learns two thin matrices A and B and uses W + B·A. That means far fewer numbers to train and store.

from peft import LoraConfig, get_peft_model
cfg = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05,
                 target_modules=["c_attn", "c_fc"], task_type="CAUSAL_LM")
model = get_peft_model(model, cfg)      # then use the same training loop

Run it with python ft.py --lora. Only the training setup changes.

Lesson from building this. With LoRA at r=8, attention layers only, lr 5e-4 and 15 epochs, the model had not learned the facts. Loss was still about 1.9 and the answers were wrong. LoRA needs a higher learning rate and usually more steps, and a bigger rank or more target layers gives it more capacity. If training loss is still high, the model is under-trained, so adjust before concluding the method failed.

Troubleshooting checklist

SymptomLikely fix
Loss barely dropsRaise learning rate or epochs. For LoRA, raise rank or add target modules.
Loss near zero but odd answers to other questionsOverfitting: add more varied data, use fewer epochs, lower the learning rate.
Output never stopsMake sure the EOS token is appended to every training example.
Out of memorySmaller batch or MAX_LEN, use LoRA/QLoRA, or a smaller model.

Exercises
